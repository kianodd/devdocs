Expo Update supports request proxying, which allows you to proxy requests to the Expo Update server through your own server. This can be useful for various reasons, such as adding custom headers, logging requests, or implementing additional security or request IP anonymization measures.

Enabling request proxying

  1. Create two proxy servers that will handle the requests:

    • One for the update asset requests (JavaScript bundles, images, and so on).
      • This must forward requests to assets.eascdn.net, the Expo Update asset server.
      • This must pass-through all URL contents (path, query parameters, and so on).
      • This must forward all request headers that:
        • start with expo- or eas-, or
        • are exactly authorization or a-im.
    • One for the update manifest requests.
      • This must forward requests to u.expo.dev, the Expo Update server.
      • This must pass-through all URL contents (path, query parameters, and so on).
      • This must pass-through all headers prefixed with expo- or eas-.
