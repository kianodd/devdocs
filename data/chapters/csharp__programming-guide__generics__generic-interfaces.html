It's often useful to define interfaces either for generic collection classes, or for the generic classes that represent items in the collection. To avoid boxing and unboxing operations on value types, it's better to use generic interfaces, such as IComparable1, on generic classes. The .NET class library defines several generic interfaces for use with the collection classes in the Generic namespace. For more information about these interfaces, see Generic interfaces.

When an interface is specified as a constraint on a type parameter, only types that implement the interface can be used. Generic interfaces can inherit from non-generic interfaces. In the .NET class library, IEnumerable1 inherits from IEnumerable. When a generic interface inherits from a non-generic interface, the type parameter typically replaces object in the overridden members. For example, IEnumerable1 uses T in place of object in the return value of GetEnumerator and in the Current property getter. Because T is used only in output positions in these members, IEnumerable1 can be marked as covariant. If T were used in an input position in an overridden member, the interface couldn't be covariant, and the compiler would generate an error.

The rules that control method overloading are the same for methods within generic classes, generic structs, or generic interfaces. For more information, see Generic Methods.

Interfaces can declare static abstract or static virtual members. Interfaces that declare either static abstract or static virtual members are almost always generic interfaces. The compiler must resolve calls to static virtual and static abstract methods at compile time. static virtual and static abstract methods declared in interfaces don't have a runtime dispatch mechanism analogous to virtual or abstract methods declared in classes. Instead, the compiler uses type information available at compile time. These members are typically declared in generic interfaces. Furthermore, most interfaces that declare static virtual or static abstract methods declare that one of the type parameters must implement the declared interface. The compiler then uses the supplied type arguments to resolve the type of the declared member.
