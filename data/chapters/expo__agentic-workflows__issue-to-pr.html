Issue to PR is an automated workflow in which a coding agent changes your code for a GitHub issue and opens a pull request (PR). Then Agentic CI tests the PR on a remote Android Emulator or iOS Simulator. You review a PR that has a verdict and evidence.

How Issue to PR works

When a person adds the agent label to an issue, these steps run. The highlighted steps run on Expo Workflows and Expo Simulators:

  1. A GitHub Action starts the Issue to PR workflow on Expo Workflows.
  2. A coding agent reads the issue and its comments, and changes the code.
  3. The workflow pushes the change to the branch agent/issue-<number>, and opens a PR that closes the issue.
  4. Agentic CI tests the PR on an Expo Simulators session, and posts the verdict on the PR.

Only people who can add labels to issues can start the agent. Read each issue before you add the label, because the agent follows the text of the issue.

Add the job script

The script does these tasks in this order:

  1. It clones the default branch, and removes the GitHub token from the remote URL of the clone.
  2. It reads the issue and the comments from the owners, members, and collaborators of the repository. Then it writes the prompt for the agent.
  3. It removes the Expo and GitHub tokens from the environment, and runs the agent in the change mode in the app directory of the clone.
  4. If the agent changed a file in .eas or .github, it stops and does not open a PR.
  5. If the agent changed no file, it adds a comment with the reason to the issue, and stops.
  6. It commits the change, pushes the branch, and opens a PR. Then it adds a comment with the PR link to the issue.

Read the result

When the agent finishes, the issue gets an Issue to PR comment with a link to the PR:

  • The branch of the PR is agent/issue-<number>.
  • The description of the PR is the summary of the agent, and ends with Closes #<number>.

Then Agentic CI tests the PR, and posts an Agentic CI comment with the verdict. To try the feature yourself, select Try this build in your browser in that comment.

If the agent changes no file, the issue gets a comment with the reason. If the agent changes a file in .eas or .github, the job fails. The issue gets no comment. The log of the agent is in the Issue to PR workflow run. The Claude Code runner saves it in the artifacts, and the other runners print it to the job log.
