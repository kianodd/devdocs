In this chapter, we'll create the first screen of the StickerSmash app.

The screen above displays an image and two buttons. The app user can select an image using one of the two buttons. The first button allows the user to select an image from their device. The second button allows the user to continue with a default image provided by the app.

Once the user selects an image, they can add a sticker to it. So, let's start creating this screen.

Break down the screen

Before we build this screen by writing code, let's break it down into some essential elements.

There are two essential elements:

  • A large image in the top half of the screen
  • Two buttons in the bottom half of the screen

The first button contains multiple components. It has a yellow background. It contains an icon and a text component inside a row.

Now that we've broken down the UI into smaller chunks, we're ready to start coding.

Display the image

We'll use expo-image library to display the image in the app. It provides a cross-platform `` component to load and render an image. It is already included in the default project template we're using.

The Image component takes the source of an image as its value. The source can be either a static asset or a URL. For example, the source required from assets/images directory is static. It can also come from Network as a uri property.

To use the Image component in src/app/(tabs)/index.tsx file:

  1. Import Image from the expo-image library.
  2. Create a PlaceholderImage variable to use assets/images/background-image.png file as the source prop on the Image component.
  3. Replace the outer View with SafeAreaView from react-native-safe-area-context. Native tabs don't add a header, so SafeAreaView keeps the screen content below the status bar on Android and iOS. The default template includes this library.
  4. Add a paddingTop to the image container with Platform.select(). On web, the tab list sits at the top of the page, so the image needs more space there.

Use native buttons with Expo UI

Our button uses React Native components, so it looks the same on every platform. Expo UI provides native components: Jetpack Compose views on Android and SwiftUI views on iOS. The default template already includes Expo UI (@expo/ui). Expo UI works in Expo Go.

Let's replace the button on Android and iOS with a native button, and keep the React Native button for web. To do this, we'll use platform-specific extensions. When button.android.tsx and button.ios.tsx exist next to button.tsx, Metro uses the file for the current platform when we import @/components/button. Web still uses button.tsx. Web uses button.tsx, because there is no button.web.tsx file. TypeScript also reads the types of @/components/button from button.tsx. So all three files must accept the same props.
