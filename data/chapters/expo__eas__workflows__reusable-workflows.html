A reusable workflow is a workflow file that other workflows can call. Use it to share whole jobs between workflow files. To share a sequence of steps inside a job, use custom functions.

For the YAML syntax of the reusable workflow and the calling job, see on.workflow_call and Workflow call jobs in the syntax reference.

How it works

A workflow can call another workflow only if that workflow declares on.workflow_call.

A calling job sets uses to the path of the reusable workflow, and with to its input values. Both workflow files must be in the .eas/workflows directory of the same project:

When the calling job runs, it starts the called run and waits for its result.

Inputs and outputs

The reusable workflow declares its inputs in on.workflow_call.inputs and reads them as ${{ inputs.<input_name> }}. The calling job sets their values in with. For the expressions and value types that with accepts, see jobs.<job_id>.with.

The reusable workflow declares its outputs in on.workflow_call.outputs. Expo Workflows evaluates them after the called run succeeds. The calling run reads them through the needs context of the calling job.

Context of a called run

A called run uses the same commit, Git ref, and github context as the run that calls it. It gets its own inputs and workflow contexts.

Environment variables do not carry over. Each job in the reusable workflow reads env from its own environment.

A called run uses the run_name and concurrency settings from the reusable workflow file. If the called run's concurrency.group matches a run above it in the call chain, Expo Workflows does not start it, and the calling job fails. For example, this happens when both workflows use a group built only from github values, such as ${{ github.ref_name }}, because both runs share that context.

Status and cancellation

The calling job ends with the status of the called run: success, failure, or canceled. If the called run fails, its errors appear on the calling job.

When you cancel the calling run, Expo Workflows also cancels the called run.

Nesting and limits

A reusable workflow can call other reusable workflows. The following limits apply:

  • You can nest calls up to 4 levels deep.
  • A workflow cannot call itself, directly or through other workflows.

Example

.eas/workflows/build.yml builds the app for one environment. It reuses an existing build when one matches the project fingerprint, creates a new build otherwise, and returns the IDs of new builds.

.eas/workflows/release.yml calls the reusable workflow twice on each push to main. The first call builds for preview. After an approval, the second call builds for production, and the workflow submits each new production build to the app stores.
