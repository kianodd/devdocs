important Expo Metadata is in beta and subject to breaking changes.

Expo Metadata is a command-line tool from Expo Services that enables you to automate and maintain your app store presence.

You need to provide a lot of information to multiple app stores before your users can use your app. This information is often about complex topics that don't apply to your app. You have to start a lengthy review process after providing the information. When the reviewer finds any issues in the information you provided, you need to restart this process.

Expo Metadata uses a store.config.json file to provide information instead of going through multiple forms in the app store dashboards and without leaving your project environment. Combined with built-in validation, you get instant feedback about the content you provide, even before any review.

Key features

Easy to configure, update, or maintain

You can start using Expo Metadata by creating a new or generating a store config from an existing app. This store config lets you quickly update the app store information without leaving your project environment. Before pushing the changes to the app stores, Expo Metadata looks for common pitfalls that might result in an app rejection.

Faster feedback loop with validation

Expo Metadata comes with built-in validation, even before anything is sent to the app stores. This validation helps you iterate faster over the information without starting a review. Instead, you can begin the review process when everything is provided, and no issues are detected.

Make sure to install the VS Code Expo Tools extension to get auto-complete, suggestions, and warnings for store.config.json files.

Extensible with dynamic store config

Expo Metadata also supports a more dynamic store config, instead of only using JSON files. This dynamic store config allows you to gather information from other places like external services. With asynchronous functions, there are no limits to adapting Expo Metadata to suit your preferred workflow.

Frequently asked questions (FAQ)

We are committed to Expo Metadata and will expand functionality over time. This also means that not all functionality is implemented in Expo Metadata. The Google Play Store is one of those features currently not implemented.

See the store config schema for all existing functionality.

Expo Metadata only sends the data from your store config to the app stores. It does not block you from using the app store dashboards if you need a feature that Expo Metadata does not cover yet.

When using Expo Metadata and editing something in the app store dashboards, make sure to run eas metadata:pull after these changes. Without updating your local store config, Expo Metadata might overwrite your changes when pushing to the app stores.

You'll need to authenticate with the app store before Expo Metadata can access the information. If you are working with a large corporate account, you might not have permission to use all functionality of Expo Metadata. While you can use Expo Metadata in these cases, it's often more challenging due to the security restrictions.
