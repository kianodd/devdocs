Unlike React Navigation, Expo Router always has access to a URL. This means screen tracking is as easy as the web.

  1. Create a higher-order component that observes the currently selected URL
  2. Track the URL in your analytics provider

Now when the user changes routes, the analytics provider will be notified.

Tracking focused screens

info Available in SDK 58 and later.

Expo Router records performance marks for navigation events. You can observe these marks and send their details to your analytics provider. This is useful when you need to track when a screen becomes focused, including when a previously mounted screen regains focus.

Enable the experimental performance integration before the root layout mounts. Observe expo-router:page-focused marks and send their details to your provider:

Replace analytics.track with your provider's event method. The buffered option includes marks recorded before the observer starts, including the initial screen. A preloaded screen does not produce a focus mark until the user navigates to it. Each mark also has a startTime in milliseconds, measured from performance.timeOrigin. If your provider expects a Unix timestamp, send performance.timeOrigin + entry.startTime.

Expo Router also records expo-router:page-preloaded, expo-router:page-blurred, expo-router:page-removed, expo-router:action-enqueued, and expo-router:action-dispatched marks. Observe these names if your solution needs more navigation events. This API is experimental and its names may change.

Migrating from React Navigation

React Navigation's screen tracking guide cannot make the same assumptions about the navigation state that Expo Router can. As a result, the implementation requires the use of onReady and onStateChange callbacks. Avoid using these methods if possible as the root `` is not directly exposed and allows cascading in Expo Router.
