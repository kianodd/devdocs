The ParadeDB extension adds full-text search to Prisma ORM 8, with results ranked by how well they match. It uses pg_search, a PostgreSQL extension from ParadeDB. pg_search adds a BM25 index, which ranks results the way most search engines do. You declare one index over the text columns to search, and then filter and rank rows by a search query.

@prisma/orm-extension-paradedb is experimental: what it offers may change in a later Prisma ORM release, so check its release notes before you upgrade.

This page assumes a Prisma ORM 8 project on PostgreSQL, such as one from Create a new app with PostgreSQL, where src/prisma/db.ts creates the client your code queries with.

pg_search has to be installed on your PostgreSQL server. Check that your provider offers it; ParadeDB's documentation lists where it runs. To run it on your machine, use the paradedb/paradedb Docker image: A database on your machine shows the Compose file, and you change its image: to paradedb/paradedb.

Your contract must be TypeScript

The search index can only be declared in a TypeScript contract, src/prisma/contract.ts; a contract.prisma contract cannot declare it yet. A project has one contract, so if yours is contract.prisma, rewrite it in TypeScript and delete contract.prisma: TypeScript schema builder shows the TypeScript form of everything you can write in contract.prisma. Then change contract in prisma.config.ts to ./src/prisma/contract.ts. When the rewrite describes the same tables, migration plan finds nothing to change.

Search

Each text column in the index has search operations, which you use in where(). A search splits the column's text and your query into words, ignoring case:

Operation Matches rows whose field
body.paradeDbMatch(query) or body.paradeDbMatchAny(query) contains any word of query
body.paradeDbMatchAll(query) contains every word of query
body.paradeDbPhrase(query) contains the words of query next to each other, in order
body.paradeDbTerm(word) contains the one word word, compared as written, so give it in lowercase
