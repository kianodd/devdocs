When you build an Android app on Windows, the native (C++) build can fail with an error like this:

Why this happens

The New Architecture compiles C++ code for each native library, and the generated object files are nested deeply under android/app/.cxx. With a project in a deep folder, or a package with a long name, their full paths exceed 260 characters, the default path limit on Windows.

The error comes from Ninja, the build tool that CMake uses. Ninja supports longer paths in version 1.12.0 and later. By default, Android builds use the Android SDK's CMake 3.22.1 package, which includes Ninja 1.10.2. Ninja 1.12 also needs long paths to be enabled in Windows.

Use a newer CMake version

Enabling long paths isn't enough on its own, because Ninja 1.10.2 doesn't support them. Install a newer CMake package, which includes a newer Ninja. For example, the Android SDK's CMake 3.31.6 package includes Ninja 1.12.1.

  1. In Android Studio, open Settings > Languages & Frameworks > Android SDK > SDK Tools, select Show Package Details, and install CMake 3.31.6 under CMake.
  2. Set the android.cmakeVersion Gradle property in the gradle.properties file in your Gradle user home, %USERPROFILE%\.gradle\gradle.properties. Create the file if it doesn't exist:
  1. Delete android/app/.cxx and android/app/build so that CMake regenerates its build files, and then build again.

In SDK 57 and later, Expo reads the android.cmakeVersion property, both in projects that use prebuild and in projects that include an android directory. This file is on your computer and isn't part of your project. Builds on Expo Build and on other computers keep using the default CMake version.

Set the CMake version in your project

You can also set the CMake version in your project, with the android.cmakeVersion option of expo-build-properties in app.json, or with the android.cmakeVersion property in android/gradle.properties. The setting then applies to every build of the project, including builds on Expo Build. Expo Build runs Android builds on Linux, where the path limit doesn't apply. CMake 3.31.6 isn't installed there, so the build fails with CMake '3.31.6' was not found in SDK, PATH, or by cmake.dir property.

Expo Build runs npx expo prebuild on its Linux build server, so cmakeVersion isn't set there. On your computer, run npx expo prebuild --clean after changing the config.

Move the project to a shorter path

To confirm that the path length is the cause, or as a workaround, move the project to a short folder such as C:\dev\my-app and build again.

info The git config core.longpaths true setting doesn't affect the Android build. It only matters if Git fails to check out files with long paths.
