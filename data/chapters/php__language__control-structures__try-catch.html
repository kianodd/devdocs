try

A block delimits a segment of code which might a Throwable error that needs handling. A block must have at least one corresponding or block.

When a Throwable error is thrown in a block, PHP will attempt to find the first matching block to handle the error. If none can be found, the call stack is unwound until a matching block is found or the global scope is reached. An uncaught object is then passed to the exception handler set with set_exception_handler, if one is set; otherwise, the script terminates with a fatal error.

catch

A block defines how to respond to a thrown Throwable error. It specifies one or more subclasses of Throwable (most commonly Exception) it can handle, and optionally a variable to which the exception is assigned.

The first block that matches the class of the thrown Throwable object will handle the error. Normal execution resumes after the block without entering any other matching blocks.

It is not recommended to catch Error objects, as they signal a programming error.

Catching an Exception

As of PHP 7.1.0, a block may specify a union of Throwable subclasses that the block should handle using the pipe (|) character. This is useful when different exceptions from different class hierarchies are handled in the same way.

Catching a union of classes to handle

Multiple blocks can be used to handle different classes of Throwable errors in different ways.

Multiple catch blocks

Throwables can be n (or re-thrown) within a block.

Nested Exception

An object thrown inside a block will not be caught by an adjacent block.

Sequential catch blocks

As of PHP 8.0.0, the variable name for a caught Throwable is optional. If not specified, the block will still execute but will not have access to the thrown object.

Omitting the caught variable

Only permitted as of PHP 8.0.0.
