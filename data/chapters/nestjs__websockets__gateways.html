Most of the concepts discussed elsewhere in this documentation, such as dependency injection, decorators, exception filters, pipes, guards, and interceptors, apply equally to gateways. Wherever possible, Nest abstracts implementation details so that the same components can run across HTTP-based platforms, WebSockets, and microservices. This section covers the aspects of Nest that are specific to WebSockets.

In Nest, a gateway is a class annotated with the @WebSocketGateway() decorator. Gateways are platform-agnostic, so they work with any WebSockets library once an adapter exists for it. Nest supports two WebSocket platforms out of the box: socket.io and ws. Choose the one that best suits your needs. You can also build your own adapter by following the adapters guide.

Hint

Gateways are providers: they can inject dependencies through the class constructor, and other classes (providers and controllers) can inject them.

Asynchronous responses

Message handlers can respond either synchronously or asynchronously, so async methods are supported. A message handler can also return an Observable, in which case each emitted value is sent to the client until the stream completes.

Lifecycle hooks

Gateways support three lifecycle hooks. Each has a corresponding interface, described in the following table:

OnGatewayInit Requires the afterInit() method, which receives the library-specific server instance as an argument.
OnGatewayConnection Requires the handleConnection() method, which receives the library-specific client socket instance as its first argument.
OnGatewayDisconnect Requires the handleDisconnect() method, which receives the library-specific client socket instance as its first argument.

Hint

Each lifecycle interface is exposed from the @nestjs/websockets package.

Warning

Nest doesn't wait for an async handleConnection() to finish before it handles the client's messages, so the hook isn't a gate: messages that arrive before it disconnects the client are still handled. To check each message, bind guards to the message handlers. To reject a client before any of its messages are handled, use connection-level middleware instead: socket.io's server.use() in afterInit(), or, with WsAdapter, a verifyClient function in the @WebSocketGateway() options.

Request-scoped gateways

Starting with NestJS v12, gateways support request-scoped providers. Nest creates a new instance of every request-scoped dependency per connected socket. That instance lives as long as the connection does, so it can safely hold per-connection state.
