The SQL query builder builds typed queries from a table, with one method per SQL clause: select(), innerJoin(), groupBy(), and the rest. It is closer to SQL than the ORM client is, and the same db gives you both. Reach for it when you need a join, aggregate, or SQL feature the ORM client doesn't expose, or when you want direct control over the generated SQL.

Some methods work only on some databases, and some fail only when the query runs. For a task-oriented guide to when and how to reach for the builder, see Advanced queries.

[The builder for SQL databases]

The SQL query builder targets SQL databases; PostgreSQL and SQLite are supported today. MongoDB has no SQL builder: use the ORM client for MongoDB queries, and the pipeline builder for aggregation pipelines.

Entry points

In Prisma ORM 8 your schema.prisma is called contract.prisma. Coming from Prisma ORM 7 gets you from a Prisma ORM 7 project to that file, and has the rest of the setup steps. Install the client with npm install @prisma/orm-postgres. Run npx prisma contract emit to write contract.json and contract.d.ts beside contract.prisma. The examples below assume your own file is in src/prisma/, next to those two files, and they write the type import path as ./contract.d, exactly like that.

You build queries from the client's sql property. Create a Postgres client with postgres(...), then reach tables through db.sql.public. public is the PostgreSQL schema your tables are in. To put a model's table in another PostgreSQL schema, such as auth, wrap the model in a namespace auth { ... } block in your contract, and you then reach its table through db.sql.auth instead. See Namespaces.

Table accessors are keyed by table name, not model name. A table name is the model's @@map value, or the model name exactly as written when the model has no @@map. In the example schema, the User model is mapped to user, so you write db.sql.public.user. The PostTag model for the join table is mapped to post_tag, so you write db.sql.public.post_tag. Column names are the field names unless a field sets @map, and for a field that does, you write the @map name everywhere in the builder. A field declared userId Uuid @map("user_id") is select('user_id') and f.user_id, and each row you get back has a user_id key.

The db.sql builder [#the-dbsql-facet]

A select(), insert(), update(), or delete() call starts a query. build() turns the chain into a query object, which the examples name plan. Nothing touches the database until you pass that object to db.query(...) or db.execute(...). You can run the same built query more than once. To see the SQL without running it, pass it to db.toSql(...). When your app shuts down, close the client with db.close().

Expressions and functions

Callback forms receive fns alongside the f argument. fns is an object of helper functions: comparisons, boolean combinations, aggregates, and raw SQL.

Built-in functions

These exist on every database:

Category Functions
Comparison eq(a, b), ne(a, b), gt(a, b), gte(a, b), lt(a, b), lte(a, b)
Membership in(expr, values), notIn(expr, values)
Boolean and(...predicates), or(...predicates)
Existence exists(subquery), notExists(subquery)
Raw SQL raw`...`.returns(typeId)

For in() and notIn(), values is an array or a subquery. All four of in(), notIn(), exists(), and notExists() take a select query that you do not call build() on.

Which aggregate functions exist depends on your database, and PostgreSQL gives you these eight. The contract type is the one you write in contract.prisma, and the PostgreSQL type is in brackets:

Function Returns
count() / count(field) number. With no argument it counts rows. With a field it counts that field's non-null values
countBigInt() / countBigInt(field) bigint. Use it when the count can pass 2^53 - 1
sum(field) number over an Int (int4) or BigInt (int8) column. A string over Decimal (numeric), a number over Float (float8)
sumBigInt(field) bigint. The sum over an integer column that can pass 2^53 - 1
avg(field) number over an Int (int4) or Float (float8) column
avgDecimal(field) An exact decimal string. The version of avg that does not round
min(field) The input column's own type. A varchar column gives a String (text)
max(field) The input column's own type. A varchar column gives a String (text)

Full-text search on PostgreSQL uses fns.fullTextMatches(column, query) to filter, fns.fullTextRank(column, query) to score, and fns.fullTextHeadline(column, query) to return the matching text with each match marked. Build query from the search text with fns.websearchToTsquery(text), fns.plaintoTsquery(text), fns.phrasetoTsquery(text), or fns.toTsquery(text), or with the tsquery template tag from @prisma/orm-postgres/target/full-text. Never pass user input to fns.toTsquery(), because text that breaks PostgreSQL's search syntax makes the query fail when it runs; use fns.websearchToTsquery() or the tsquery tag for user input. Full-text search on the ORM client reference explains what each of these does, and the index that lets PostgreSQL search without reading every row.

To search a @@fullTextIndex, pass the index from the table's indexes in place of the column: fns.fullTextMatches(post.indexes.post_search, q) and fns.fullTextRank(post.indexes.post_search, q), where post is db.sql.public.post. The query reads the index's fields, weights and language from the contract, so it searches every field of a weighted index and PostgreSQL uses the index. To search several columns that no index covers, build the search document with fullTextDocument from @prisma/orm-postgres/target/full-text.

Each of the three full-text functions takes an options object as its last argument, and each accepts language. Pass the same language to the function that builds query, as in fns.fullTextMatches(f.title, fns.websearchToTsquery(q, { language: 'german' }), { language: 'german' }). fullTextRank also takes normalization and coverDensity, which the ORM client reference describes. fullTextHeadline also takes these options:

  • startSel and stopSel: the text put before and after each match. PostgreSQL uses <b> and </b> when you leave them out.
  • maxWords and minWords: the longest and shortest headline, in words. minWords must be lower than maxWords.
  • highlightAll: true: return the whole text with every match marked, instead of a short excerpt around the matches.

fns.raw and .returns()

Write a raw SQL fragment as a tagged template, and interpolate columns, typed expressions, and bare JavaScript values with ${...}. For a bare value, the builder picks the type id from its JavaScript type. Binding a bare value with param() lists which JavaScript type becomes which type id, and shows how to choose a different one with param(...). Call .returns(typeId) to declare the fragment's result type.

Options

Name Type Required Description
SQL fragment Tagged template Yes The raw SQL, with ${...} interpolations for columns and values.
.returns(typeId) string, or { codecId, nullable } Yes, always Declares the result type, for example 'pg/int4@1', 'pg/text@1'. For a fragment used as a where() predicate, write .returns('pg/bool@1').

Remarks

  • Always call .returns(). Nothing in the builder accepts a fragment without it.
  • .returns() only tells TypeScript what type to expect. It does not convert the value. Convert the value in JavaScript, or run the statement with db.raw.sql and .returnsRow(), which does decode.
  • Use fns.raw for any SQL feature without a dedicated helper: COALESCE, CAST, LENGTH, UPPER, EXTRACT, and so on. There is no fns.coalesce and no fns.cast.

Streaming vs. collecting

await db.query(plan) collects every row into an array, which is the common case and what every example on this page uses. You can also loop the same result with for await to handle one row at a time. On PostgreSQL every row is loaded before the loop starts, so for await saves nothing there. Use await. The exception is a client created with the cursor option, which reads rows through a server-side cursor in batches.

Keep the result in a variable, as in const result = db.query(plan), and you can await result as many times as you like. You cannot mix await and for await on the same result, and you cannot for await it twice. Either one throws an error whose code is RUNTIME.ITERATOR_CONSUMED. See AsyncIterableResult.
