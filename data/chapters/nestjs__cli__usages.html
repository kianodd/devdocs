nest new

Creates a new (standard mode) Nest project, or with --minimal a one-file project.

Description

Creates and initializes a new Nest project. The command prompts for any information you don't pass as an option: the project name, the package manager, the module system (ESM or CommonJS), and whether to set up NestJS Observe.

Hint

In non-interactive environments, such as CI, pass the project name and --package-manager. The module system then defaults to ESM, and Observe is set up only if you pass --observe.

Hint

Choosing ESM scaffolds an ESM-first project that uses Vitest for testing. Choosing CommonJS scaffolds the traditional layout, which uses Jest. Both variants use oxlint for linting.

The command:

  • Creates a folder with the given <name>
  • Populates the folder with configuration files
  • Creates subfolders for source code (/src) and end-to-end tests (/test)
  • Populates the subfolders with default files for application components and tests
  • If Observe was set up, offers to link the project to it once the dependencies are installed (in an interactive terminal only). Accepting runs npx @nestjs/observe link, which writes the app key and secret into .env - see Linking from the terminal

One-file projects

nest new <name> --minimal generates a real Nest application without the layout around it, for a small project or a first version:

Run it with npm run start:dev. It goes through the CLI, like any other Nest project, because the TypeScript compiler has to emit decorator metadata for injection by type to work. Under a tool that doesn't emit it, such as tsx, appService above is undefined.

There's no nest-cli.json, because the CLI's defaults already describe this layout, and no tests, linter, formatter, or README. Add any of them when you need them.

nest generate works here as it does anywhere else. With no *.module.ts file to register things in, it uses the module in src/main.ts:

This writes src/users/ and adds UsersModule to the imports in src/main.ts. Spec files are left out while package.json doesn't list @nestjs/testing: install it, or pass --spec, to get them. When src/main.ts gets long, move the module to src/app.module.ts and export it, and nest generate registers things there instead.

The other options to nest new apply, with these differences:

  • --language js is refused. JavaScript needs Babel and its own entry file to run decorators, so the project wouldn't stay one file.
  • The project is always ESM, and you aren't prompted for a module system. For CommonJS, generate a standard project.
  • --observe wires the SDK into src/main.ts. npx @nestjs/observe link then writes the key pair, as usual. Without --observe, adding the SDK later takes the three edits in its quick start, because link looks for the root module in a file that main.ts imports.
  • --skip-tests has nothing to skip.

nest upgrade

Upgrades an existing project to the latest NestJS major version.

Description

Run from the root of a NestJS v11 project, nest upgrade updates your dependencies to v12 and applies the mechanical parts of the migration:

  • Refuses to run on Node.js releases that lack require(esm) (anything older than v20.19, or v22.x older than v22.12)
  • Bumps every recognized @nestjs/* package to its v12-compatible major (@nestjs/graphql, @nestjs/apollo, and @nestjs/mercurius go to v14), and reports any other @nestjs/* package it doesn't recognize so you can review it yourself
  • Bumps TypeScript to v6 (required by the v12 CLI and schematics), and raises engines.node in package.json to >=20.19.0 if it declares a lower floor
  • Migrates nest-cli.json off the deprecated webpack / webpackConfigPath options and onto --builder rspack, updating matching package.json scripts
  • Renames the GraphQL playground option to graphiql, switches subscriptions from subscriptions-transport-ws to graphql-ws, and swaps the packages accordingly
  • Replaces the legacy nats package with @nats-io/transport-node / @nats-io/nats-core and rewrites nats imports
  • Moves library-specific @nestjs/config settings under validationOptions.libraryOptions and bumps Joi to v18 (the first release implementing Standard Schema)
  • Bumps Jest to v30 (and @types/jest / ts-jest to matching releases) where present, and warns that Jest can require() the ESM-only v12 packages only on Node.js v24.9+
  • Optionally installs and wires up @nestjs/observe. It prompts, unless you pass --observe or --no-observe
  • Checks tsconfig.json and tsconfig.build.json for settings that TypeScript 6 or the ESM-only packages no longer support, such as a legacy moduleResolution or a missing rootDir
  • Scans your sources and prints notes about behavior that changed but can't be migrated automatically, such as lifecycle hook ordering, refined pipe signatures, and structured logging params

The command finishes by installing the updated dependencies (unless --skip-install is passed) and printing a report of everything it changed, warned about, and left for you.

Warning

nest upgrade only bumps the local @nestjs/cli dependency. Update a globally installed CLI yourself with npm i -g @nestjs/cli@latest, and do it before running the upgrade, because the command itself ships with the CLI.

Hint

The command deliberately does not migrate your project to ESM, Vitest, or oxlint. Those are the defaults for newly generated v12 projects, but existing projects can adopt them on their own schedule. See the migration guide for the full picture.

nest deploy

Deploys your application to the cloud, powered by Mau.

Description

nest deploy is a thin wrapper around the Mau CLI. It locates the Mau binary and forwards every argument you pass to mau deploy, so any option Mau supports works here unchanged.

If Mau is not installed in your project, the command offers to add @nestjs/mau as a dev dependency and then continues. In a non-interactive environment (e.g., CI), the command fails instead of prompting, so install Mau explicitly first:

Once Mau starts, it owns the terminal, so its output and prompts reach you directly. See the Deployment chapter for what Mau does and how to configure it.
