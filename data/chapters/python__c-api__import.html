Given a module name (possibly of the form package.module) and a code object read from a Python bytecode file or obtained from the built-in function [compile], load the module. Return a new reference to the module object, or NULL with an exception set if an error occurred. name is removed from [sys.modules] in error cases, even if name was already in [sys.modules] on entry to :c`PyImport_ExecCodeModule`. Leaving incompletely initialized modules in [sys.modules] is dangerous, as imports of such modules have no way to know that the module object is an unknown (and probably damaged with respect to the module author's intents) state.

The module's [~module.__spec__] and [~module.__loader__] will be set, if not set already, with the appropriate values. The spec's loader will be set to the module's [!__loader__] (if set) and to an instance of [~importlib.machinery.SourceFileLoader] otherwise.

The module's [~module.__file__] attribute will be set to the code object's [~codeobject.co_filename].

This function will reload the module if it was already imported. See :c`PyImport_ReloadModule` for the intended way to reload a module.

If name points to a dotted name of the form package.module, any package structures not already created will still not be created.

See also :c`PyImport_ExecCodeModuleEx` and :c`PyImport_ExecCodeModuleWithPathnames`.

This function is a building block that enables embedders to implement the :py`~importlib.abc.Loader.create_module` step of custom static extension importers (e.g. of statically-linked extensions).

spec must be a [~importlib.machinery.ModuleSpec] object.

initfunc must be an initialization function , the same as for :c`PyImport_AppendInittab`.

On success, create and return a module object. This module will not be initialized; call :c`PyModule_Exec` to initialize it. (Custom importers should do this in their :py`~importlib.abc.Loader.exec_module` method.)

On error, return NULL with an exception set.

For modules using legacy single-phase initialization , most of the import process is done in this function, rather than in extra steps that importers typically take after :py`~importlib.abc.Loader.create_module`. Specifically:

  • The module is added to [sys.modules] under the spec's :py`~importlib.machinery.ModuleSpec.name` as part of initialization.
  • If a single-phase module was previously imported under the same :py`~importlib.machinery.ModuleSpec.name` by this function or as a built-in module (for example, one registered with :c`PyImport_AppendInittab`), Python may reuse the previous module's contents instead of calling initfunc again.
  • The module will be fully initialized by initfunc. Calling :c`PyModule_Exec` on it will have no effect, though it is still recommended, in case the module later switches to multi-phase initialization .
  • Also, if the spec's :py`!name` contains dots, this name is used for prepending a parent package to the new module's [~module.__name__].
