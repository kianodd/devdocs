An extension is an npm package that adds something Prisma ORM does not do on its own: a column type such as a vector or a geometry, an index type, query operations (new functions you can call in a query, such as pgvector's cosineDistance), or middleware, which runs your own code before and after every query. To use PostgreSQL you install @prisma/orm-postgres, and to use MongoDB you install @prisma/orm-mongo, because support for a database comes from an extension too.

Installing the package is not the whole job, because you register an extension in two places. It goes in prisma.config.ts, so that the command line tools know about it, and in db.ts, the file where you create the client, so that your queries can use what it adds. @prisma/orm-postgres is the package you call directly: ormConfig(...) in prisma.config.ts and postgres(...) in db.ts. Other extensions are listed in the extensions array passed to those two calls. Using extensions shows both registrations, with the install command, for pgvector. Middleware is the exception, because you register it on the client only, and How middleware works covers that.

Your contract is what Prisma ORM 8 calls your schema: contract.prisma in place of schema.prisma. If you have a Prisma ORM 7 project, Coming from Prisma ORM 7 says what replaced schema.prisma, @prisma/client, and $use.

Catalog

The extension directory has the install command and the registration snippet for each entry below. MySQL's library, @prisma/orm-mysql, is an early preview for migrations, reads and writes, and Supported databases says what it covers and what is planned. An entry marked experimental works today, but its API can change between releases.

Three of these have their own page: PostGIS, ParadeDB, and arktype-json. Using extensions walks through pgvector.

In the Supabase row, role-bound clients are client instances pinned to a particular PostgreSQL role, so the database applies that role's row-level security policies to whatever you query through them.

Publish your own

An extension you write yourself is an npm package with one entry point for the command line tools and one for your application. Name your two entry points control and runtime, as pgvector does and as the call for extension authors describes. Middleware ships a single entry point instead, because it is only ever registered on the client.

Name the package prisma-orm-<name>, or @your-scope/prisma-orm-<name> if you publish under your own npm scope. List the keyword prisma-orm-extension in its package.json, so that people and tools searching npm can find every community Prisma ORM 8 extension:

To write middleware, follow Authoring custom middleware. If you are adding a whole database, @prisma/orm-postgres is the one to copy for a SQL database and @prisma/orm-mongo for a document database. Once your package is on npm, submit it to the directory, and a maintainer reviews your entry before it appears in the catalog.
