To convert a non-unique index to a unique index , use the [collMod] command. The collMod command provides options to verify that your indexed field contains unique values before you complete the conversion.

About this Task

The collMod command converts the existing index. MongoDB scans the index for duplicate keys and then marks the index as unique.

Keep the following behavior in mind when you convert an index:

  • Set prepareUnique to true before you convert the index. If prepareUnique is false, collMod with unique: true returns an error.
  • Run the prepareUnique modification in a separate collMod command. You cannot combine prepareUnique with other index modifications.
  • You cannot set prepareUnique on an index in a time series collection. MongoDB returns an error.
  • If another operation modifies or drops the index while collMod converts it, the command fails. Rerun the command after the other operation completes.

For sharded collections, the following behavior also applies:

  • If any shard contains duplicate keys, collMod returns CannotConvertIndexToUnique. MongoDB does not convert the index on any shard.
  • If the index key conflicts with the shard key, setting prepareUnique fails. To learn which indexes can be unique on a sharded collection, see sharded-clusters-unique-indexes.

Before you Begin

Populate sample data

Create the [apples] collection:

`javascript db.apples.insertMany( [ { type: "Delicious", quantity: 12 }, { type: "Macintosh", quantity: 13 }, { type: "Delicious", quantity: 13 }, { type: "Fuji", quantity: 15 }, { type: "Washington", quantity: 10 } ] )`

Create a single field index

Add a single field index on the [type] field:

`javascript db.apples.createIndex( { type: 1 } )`

Steps

Prepare the index to be converted to a unique index

Run [collMod] on the [type] field index and set [prepareUnique] to `true`:

`javascript db.runCommand( { collMod: "apples", index: { keyPattern: { type: 1 }, prepareUnique: true } } )`
