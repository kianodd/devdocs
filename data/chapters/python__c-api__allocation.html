Initialize a newly allocated object op with its type and initial reference. Returns the initialized object. Other fields of the object are not initialized. Despite its name, this function is unrelated to the object's [~object.__init__] method (:c`~PyTypeObject.tp_init` slot). Specifically, this function does not call the object's [!__init__] method.

In general, consider this function to be a low-level routine. Use :c`~PyTypeObject.tp_alloc` where possible. For implementing :c`!tp_alloc` for your type, prefer :c`PyType_GenericAlloc` or :c`PyObject_New`.

This does everything :c`PyObject_Init` does, and also initializes the length information for a variable-size object.

Allocates a new Python object using the C structure type TYPE and the Python type object typeobj (PyTypeObject*) by calling :c`PyObject_Malloc` to allocate memory and initializing it like :c`PyObject_Init`. The caller will own the only reference to the object (i.e. its reference count will be one).

Avoid calling this directly to allocate memory for an object; call the type's :c`~PyTypeObject.tp_alloc` slot instead.

When populating a type's :c`~PyTypeObject.tp_alloc` slot, :c`PyType_GenericAlloc` is preferred over a custom function that simply calls this macro.

This macro does not call :c`~PyTypeObject.tp_alloc`, :c`~PyTypeObject.tp_new` ([~object.__new__]), or :c`~PyTypeObject.tp_init` ([~object.__init__]).

This cannot be used for objects with :c`Py_TPFLAGS_HAVE_GC` set in :c`~PyTypeObject.tp_flags`; use :c`PyObject_GC_New` instead.

Memory allocated by this macro must be freed with :c`PyObject_Free` (usually called via the object's :c`~PyTypeObject.tp_free` slot).

Like :c`PyObject_New` except:

  • It allocates enough memory for the TYPE structure plus size (Py_ssize_t) fields of the size given by the :c`~PyTypeObject.tp_itemsize` field of typeobj.
  • The memory is initialized like :c`PyObject_InitVar`.

This is useful for implementing objects like tuples, which are able to determine their size at construction time. Embedding the array of fields into the same allocation decreases the number of allocations, improving the memory management efficiency.

Avoid calling this directly to allocate memory for an object; call the type's :c`~PyTypeObject.tp_alloc` slot instead.

When populating a type's :c`~PyTypeObject.tp_alloc` slot, :c`PyType_GenericAlloc` is preferred over a custom function that simply calls this macro.

This cannot be used for objects with :c`Py_TPFLAGS_HAVE_GC` set in :c`~PyTypeObject.tp_flags`; use :c`PyObject_GC_NewVar` instead.

Memory allocated by this function must be freed with :c`PyObject_Free` (usually called via the object's :c`~PyTypeObject.tp_free` slot).

Object which is visible in Python as None. This should only be accessed using the :c`Py_None` macro, which evaluates to a pointer to this object.
