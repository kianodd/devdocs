Creating a safe area ensures your app screen's content is positioned correctly. This means it doesn't get overlapped by notches, status bars, home indicators, and other interface elements that are part of the device's physical hardware or are controlled by the operating system. When the content gets overlapped, it gets concealed by these interface elements.

Usage

You can directly use SafeAreaView to wrap the content of your screen's component. It is a regular `` with the safe area insets applied as extra padding or margin.

Import and add SafeAreaProvider to the root component file (such as App.tsx) before using SafeAreaView in your screen component.

Alternate: useSafeAreaInsets hook

Alternate to SafeAreaView, you can use useSafeAreaInsets hook in your screen component. It provides direct access to the safe area insets, allowing you to apply padding for each edge of the `` using an inset from this hook.

Usage with web

On web, use CSS env(safe-area-inset-*) values for safe-area spacing. The browser applies these values across client rendering, server rendering, and static generation. CSS safe-area spacing does not require the react-native-safe-area-context library.

The browser provides the safe-area-inset-* environment variables. These values specify the distance from their respective edge of the viewport to the safe area, keeping content clear of notches and rounded corners. The env() function is used to read these values. See the CSS env() reference for details.

The browser updates this spacing without a React state update. Keep a corresponding src/app/index.tsx route using react-native-safe-area-context for Android and iOS.

Static and server exports include the stylesheet in the initial HTML.

In development, async routes can load layout CSS after streamed content and cause a layout shift. To avoid this development limitation, render the rules in a <style> element inside the <head> of your Root HTML component. Use src/app/+html.tsx for this component. CSS imports in +html.tsx are not supported.

In SDK 58 and later, Expo Router disables automatic safe-area measurements on web to preserve streamed content during hydration. Do not add another SafeAreaProvider to restore these measurements. Its updates can interrupt hydration and discard pending streamed content, even if you provide initialMetrics.

See the safe-area context reference for the behavior of its hooks and components. CSS values do not change the numbers returned by these hooks.

Without Expo Router, the library's provider still supports web measurements. If you use its components or hooks, configure SafeAreaProvider as described in the usage section. CSS remains the recommended approach for web spacing.
