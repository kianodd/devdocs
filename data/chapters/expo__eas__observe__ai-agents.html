The Expo Observe dashboard and the eas observe commands show the metrics, events, errors, and sessions your app sends. An AI agent can read the same data and do the analysis for you: compare releases, find the slowest sessions, and explain what the slow ones have in common.

There are two ways to give an agent access to your data:

  • Expo MCP Server: the agent calls the Expo Model Context Protocol (MCP) Server directly. It works in Claude, Claude Code, Codex, Cursor, and VS Code. The agent does not need terminal access.
  • EAS CLI: the agent runs eas observe commands in your terminal. It covers everything the CLI covers, including errors, and the eas-observe skill teaches the agent how to use it.

You can set up both. An agent with both reads metrics through the server and falls back to the CLI for errors and scripts.

Either way, your app must already send data. Follow Get started first if it does not.

Option 1: Expo MCP Server

The Expo MCP Server exposes read-only tools for app versions, metric summaries, metric samples, routes, user-defined events, and session timelines. The agent signs in with your Expo account, so it needs no access token. Each tool call counts toward your account's Expo MCP Server usage. Plan limits are the same as in the dashboard and the EAS CLI. See Tools for the current list.

Add the Expo connector to your Claude account. It works on the web, desktop, and mobile apps, with no installation on your machine.

Example prompts

Ask questions the way you would ask a colleague. The agent picks the tools or commands, fills in the project, platform, and time range, and chains several calls when one answer depends on another.

  • "Did startup get slower in the latest iOS release?"
  • "Find the five slowest cold launches this week and tell me what those devices have in common."
  • "Which routes have the worst time to interactive on Android?"
  • "How many users completed onboarding since the last update?"
  • "How long do over-the-air updates take to download on cellular?"
