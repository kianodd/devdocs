important Server headers are available in SDK 54 and later, and requires expo-server to serve your exported application.

Server headers in Expo Router allow you to set custom HTTP headers for security, caching, cookies, and custom metadata on route responses. Global headers apply to HTML, API route, and data loader responses. In SDK 58 and later, use pageHeaders to configure headers for specific HTML pages. These options do not apply to static assets such as images, fonts, or JavaScript bundles.

Configuration

Headers are configured as an object where keys are header names and values are either strings or arrays of strings.

How it works

Output modes

Server headers work with both output modes configured in your app config:

  • static: expo-server applies headers when serving pre-rendered HTML and loader data files
  • server: The server applies headers to dynamically rendered HTML, API route, and data loader responses

The development server and npx expo serve support global and path-specific headers. For production deployments, use expo-server or Expo Hosting to apply these headers. Other static hosts need their own header configuration. For loader caching defaults and development behavior, see Data loaders: Cache defaults.

Header precedence

For a header with a string value, the following order applies, from highest to lowest priority:

  1. Headers set by the route response.
  2. Matching pageHeaders rules, for HTML pages.
  3. Global headers.

When multiple pageHeaders rules match, later rules override earlier rules for the same header. Header names are case-insensitive. The server appends array values, allowing multiple values such as Set-Cookie headers.

For example, suppose global headers sets Cache-Control: public, max-age=3600. A matching pageHeaders rule can override it with private, max-age=60. If the page response sets no-store, that value takes precedence over both settings.

Known limitations

  • Redirects: Headers do not apply to redirect responses
  • Static assets: These options do not apply to images, fonts, or JavaScript bundles
