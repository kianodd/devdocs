Linux distributions use systemd to start up and manage services through standard command-line tools. If you installed MongoDB Enterprise or MongoDB Community through the package manager, you can manage the [~bin.mongod] process through the systemctl command.

Syntax

Commands

stub-columns : 1

widths : 20 80

  • Command
    • Description
  • [enable]
    • Configures systemd to start the MongoDB service during boot.
  • [restart]
    • Restarts the MongoDB service.
  • [start]
    • Starts the MongoDB service.
  • [status]
    • Shows the status of the MongoDB service.
  • [stop]
    • Stops the MongoDB service.

Compatibility

On self-managed deployments, you can manage the [~bin.mongod] process with the systemctl command on any supported systemd-based distribution of Linux.

For details on supported platforms, see:

  • Supported Platforms for MongoDB Enterprise
  • Supported Platforms for MongoDB Community

Behavior

User Privileges

Most commands that run through systemd require a user with elevated privileges. While the root user can administer the [~bin.mongod] process directly through the systemctl command, other users must run these commands with sudo privileges.

System Journal

When run through systemd with the default configuration, [~bin.mongod] logs messages through the system journal. The journal allows you to search for specific issues or messages with the journalctl command.
