A server-only function evaluated at build-time in a Node.js environment by Expo CLI. This means it has access to __dirname, process.cwd(), process.env, and more. It also has access to every environment variable that's available in the process. However, the values prefixed with EXPO_PUBLIC_ do not run in a browser environment, so it cannot access browser APIs such as localStorage or document. It also cannot access native Expo APIs such as expo-camera or expo-location.

generateStaticParams cascades from nested parents down to children. The cascading parameters are passed to every dynamic child route that exports generateStaticParams.

Now the dynamic child routes will be invoked twice, once with { id: 'one' } and once with { id: 'two' }. All variations must be accounted for.

Read files using process.cwd()

Since Expo Router compiles your code into a separate directory you cannot use __dirname to form a path as its value will be different than expected.

Instead, use process.cwd(), which gives you the directory where the project is being compiled.

Root HTML

By default, every page is wrapped with some small HTML boilerplate, this is known as the root HTML.

You can customize the root HTML file by creating a src/app/+html.tsx file in your project. This file exports a React component that only ever runs in Node.js, which means global CSS cannot be imported inside of it. The component will wrap all routes in the app directory. This is useful for adding global <head> elements or disabling body scrolling.

Note: Global context providers should go in the Root Layout component, not the Root HTML component.

In SDK 58 and later, static rendering requires custom HTML components to render the values from useServerDocumentContext(). Render headNodes inside <head> and bodyNodes after children inside <body>.

  • The children prop comes with the root <div id="root" /> tag included inside.
  • The pathname and params props contain the rendered route's pathname and URL parameters. Available in SDK 58 and later.
  • headNodes contains generated metadata and styles, such as React Native web styles.
  • bodyNodes includes font resources and JavaScript bundles.
  • Global CSS should not be imported into this file. Instead, use the Root Layout. Expo Router traverses the dependency graph starting from the root layout, so importing CSS elsewhere can cause unexpected loading order where node_modules CSS takes precedence over your custom styles.
  • Browser APIs like window.location are unavailable in this component as it only runs in Node.js during static rendering.

Meta tags

In SDK 58 and later, export a generateMetadata() function from a route to include metadata in its generated HTML. Expo CLI resolves this function at build time for each static path.

The function can be asynchronous and receives undefined as its first argument and the route's parameters as its second argument. Static rendering does not provide a request, including during development. See metadata with server rendering for supported fields and dynamic examples.

Use generateMetadata() for metadata that must be present before JavaScript runs. The component from `expo-router/head` can update metadata after hydration, but its tags are not included in the initial static HTML. In SDK 57 and earlier, use for initial static metadata.

When upgrading from SDK 57, follow Migrate static page metadata to move existing Head tags and document attributes.

Common questions

How do I add a custom server?

There is no prescriptive way to add a custom server. You can use any server you want. However, you will need to handle dynamic routes yourself. You can use the generateStaticParams function to generate static HTML files for known routes.

In SDK 58 and later, set apiRoutes: true in the expo-router config plugin to add API routes alongside your static HTML. To render pages at request time, use server rendering.

Server-side rendering

Rendering at request-time is not supported with web.output: 'static'. To render pages dynamically on each request, use server rendering with web.output: 'server' instead.

Where can I deploy statically rendered websites?

You can deploy your statically rendered website to any static hosting service. Here are some popular options:

  • Expo Hosting
  • Netlify
  • Cloudflare Pages
  • AWS Amplify
  • Vercel
  • GitHub Pages
  • Render
  • Surge

Note: You don't need to add Single-Page Application styled redirects to your static hosting service. The static website is not a single-page application. It is a collection of static HTML files.
