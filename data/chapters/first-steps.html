This set of articles covers the core fundamentals of Nest. To introduce the essential building blocks of a Nest application, we'll build a basic CRUD application whose features cover a lot of ground at an introductory level.

Language

Nest is written in TypeScript and runs on Node.js, and it supports both TypeScript and plain JavaScript. Because Nest relies on the latest language features, using it with plain JavaScript requires Babel.

Most examples in this documentation use TypeScript, but you can switch any code snippet to plain JavaScript syntax with the language toggle in the upper-right corner of the snippet.

Prerequisites

Make sure that Node.js is installed on your operating system. Running a Nest application requires v20.19 or later (or v22.12+ on the 22.x line). The Nest CLI's generators (such as nest new and nest generate) require v22.22.3+, v24.15+, or v26+. We recommend the latest active LTS release, which satisfies both requirements.

The CLI asks which module system to use: ESM (the default), which uses Vitest as the test runner, or CommonJS, which uses Jest.

It also asks whether to set up NestJS Observe, the official observability platform for Nest. If you answer yes, the generated project includes the @nestjs/observe SDK, already wired into AppModule and NestFactory.create(). In an interactive terminal, the prompt defaults to yes; in non-interactive environments, such as CI, it is skipped and Observe is not added. Pass --observe or --no-observe to skip the prompt either way. See the Observability chapter for what Observe covers.

If you set up Observe, the CLI then offers to link the new project to it, once the dependencies are installed. Accepting prints a code to approve at observe.nestjs.com/link (signing up first if you don't have an account; the free plan needs no payment details), and the CLI then writes the app key and secret into .env and makes every nest start script (start, start:dev, and start:debug) load it. Requests, background jobs, errors, and distributed traces start reporting the next time you start the application. To link later, or when the CLI doesn't offer it (without a terminal, or with --skip-install), run npx @nestjs/observe link in the project directory - see Linking from the terminal.

By default, if an error occurs while the application is being created, the process exits with code 1. To have the error thrown instead, disable the abortOnError option (e.g., NestFactory.create(AppModule, { abortOnError: false })).

Platform

Nest is designed to be platform-agnostic. Platform independence lets you create reusable logical parts that can be used across several different types of applications. Nest can work with any Node.js HTTP framework once an adapter is created for it. Three HTTP platforms are supported out of the box: Express, Fastify, and the node:http module built into Node.js. Choose the one that best suits your needs (see HTTP adapters).
platform-express Express is a well-known, minimalist web framework for Node.js. It is a battle-tested, production-ready library with extensive community resources. Nest uses the @nestjs/platform-express package by default, so no setup is required.
platform-fastify Fastify is a high-performance, low-overhead framework focused on efficiency and speed. To learn how to use it, see Fastify adapter.
platform-node The NodeAdapter runs Nest directly on the node:http module of Node.js, and is the fastest of the three. Its request and response objects come with the Express-style helpers, so most Express middleware works with it. We recommend it starting with v12.3, and it will become the default in v13. To learn how to use it, see Node adapter.

Each platform exposes its own application interface: NestExpressApplication, NestFastifyApplication, and NestNodeApplication, respectively.

When you pass a type to the NestFactory.create() method, as in the example below, the app object exposes methods that are available only on that platform. You don't need to specify a type unless you want to access the underlying platform API.
