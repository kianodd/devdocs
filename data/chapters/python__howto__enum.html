Some rules:

  1. When subclassing [Enum], mix-in types must appear before the [Enum] class itself in the sequence of bases, as in the [IntEnum] example above.
  2. Mix-in types must be subclassable. For example, [bool] and [range] are not subclassable and will throw an error during Enum creation if used as the mix-in type.
  3. While [Enum] can have members of any type, once you mix in an additional type, all the members must have values of that type, e.g. [int] above. This restriction does not apply to mix-ins which only add methods and don't specify another type.
  4. When another data type is mixed in, the [~Enum.value] attribute is not the same as the enum member itself, although it is equivalent and will compare equal.
  5. A data type is a mixin that defines [~object.__new__], or a [~dataclasses.dataclass]
  6. %-style formatting: %s and %r call the [Enum] class's [~object.__str__] and [~object.__repr__] respectively; other codes (such as %i or %x for IntEnum) treat the enum member as its mixed-in type.
  7. Formatted string literals , [str.format], and [format] will use the enum's [~object.__str__] method.

Note

Because [IntEnum], [IntFlag], and [StrEnum] are designed to be drop-in replacements for existing constants, their [~object.__str__] method has been reset to their data types' [~object.__str__] method.

How are Enums and Flags different?

Enums have a custom metaclass that affects many aspects of both derived [Enum] classes and their instances (members).

Enum Classes

The [EnumType] metaclass is responsible for providing the [~object.__contains__], [~object.__dir__], [~object.__iter__] and other methods that allow one to do things with an [Enum] class that fail on a typical class, such as list(Color) or some_enum_var in Color. [EnumType] is responsible for ensuring that various other methods on the final [Enum] class are correct (such as [~object.__new__], [~object.__getnewargs__], [~object.__str__] and [~object.__repr__]).

Flag Classes

Flags have an expanded view of aliasing: to be canonical, the value of a flag needs to be a power-of-two value, and not a duplicate name. So, in addition to the [Enum] definition of alias, a flag with no value (a.k.a. 0) or with more than one power-of-two value (e.g. 3) is considered an alias.

Enum Members (aka instances)

The most interesting thing about enum members is that they are singletons. [EnumType] creates them all while it is creating the enum class itself, and then puts a custom [~object.__new__] in place to ensure that no new ones are ever instantiated by returning only the existing member instances.
