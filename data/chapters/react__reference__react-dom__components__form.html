The built-in browser <form> component lets you create interactive controls for submitting information.

Reference

<form>

To create interactive controls for submitting information, render the built-in browser <form> component.

See more examples below.

Props

<form> supports all common element props.

  • action: A string containing a URL, or a function. If you pass a URL, the form behaves like a standard HTML form. If you pass a function, it handles the submission. See Handling form submission with an action prop.
    • If you pass a function to action, React runs it in a Transition following the Action prop pattern.
    • The function may be async. React calls it with a single argument containing the form data of the submitted form.
    • A formAction prop on a <button>, <input type="submit">, or <input type="image"> overrides this action.
  • method: A string that specifies the HTTP method to use when action is a URL. Defaults to get.
  • onSubmit: An Event handler function. Fires when the form is submitted. See Handling form submission with an event handler.

Caveats

  • If you pass a function to action or formAction, the HTTP method will be POST regardless of the value of the method prop.
  • If you pass a function to action or formAction, React resets all uncontrolled field elements after the Action succeeds. See Preserving form values after an Action.

Usage

Handling form submission with an event handler

Pass a function to the onSubmit event handler to run code when the form is submitted. By default, the browser sends the form data to the current URL and refreshes the page. Calling e.preventDefault() in the event handler overrides this behavior.

If you also pass a function to action, React runs it after onSubmit unless onSubmit calls e.preventDefault().

onSubmit works in every version of React and gives you direct access to the submit event. Starting in React 19, the action prop is the preferred API for form submissions. With action, React runs the submission in a Transition and manages pending state and concurrency across multiple submissions. You can also use optimistic updates, Error Boundaries, and Server Functions.

Handling form submission with an action prop

Pass a function to the action prop to run it when the form is submitted. React calls the function with a FormData object containing the values of every input with a name attribute. Your inputs can be uncontrolled. You don't need value/onChange pairs, an onSubmit handler, or e.preventDefault().

When you pass a function to action, React:

  • Runs the function in a Transition.
  • Makes the pending state available to child components via useFormStatus.
  • Propagates any errors to the nearest Error Boundary.
  • Resets the form's uncontrolled fields when the function succeeds. To keep their values, see Preserving form values after an Action.

Because the Action runs in a Transition, you can also use useActionState to manage form state and useOptimistic for optimistic UI. For Server Functions and progressive enhancement, see Handling form submission with a Server Function.

Handling form submission with a Server Function

A <form>'s action prop can run a Server Function (a function marked with 'use server') when the user submits the form. Users can submit that form before JavaScript loads or when JavaScript is disabled. This matches how forms behave when you pass a URL to action.

React calls the Server Function with the form's FormData and includes every input with a name attribute. To pass additional data, such as an ID from props, see Passing extra data to an Action.

Passing extra data to an Action

An Action receives the submitted FormData. To include data the user did not enter, such as an ID from props, use one of these approaches:

  • Hidden fields add the value to FormData. The value appears in the HTML, and formData.get returns a string. Users can submit the form before JavaScript loads.
  • Binding with bind passes the value as an argument to a Server Function, before formData. The argument keeps its type, so a number stays a number. It must be serializable. Users can submit the form before JavaScript loads.
  • A function in the component reads props and state directly. It runs after JavaScript loads, then calls a Server Function with those values.

The client sends hidden field values and bound arguments. Check on the server that the logged-in user is allowed to perform the Action. See Security considerations.

Optimistically updating form data

The useOptimistic Hook provides a way to optimistically update the user interface before a background operation, like a network request, completes. In the context of forms, this technique helps to make apps feel more responsive. When a user submits a form, instead of waiting for the server's response to reflect the changes, the interface is immediately updated with the expected outcome.

For example, when a user types a message into the form and hits the "Send" button, the useOptimistic Hook allows the message to immediately appear in the list with a "Sending..." label, even before the message is actually sent to a server. This "optimistic" approach gives the impression of speed and responsiveness. The form then attempts to truly send the message in the background. Once the server confirms the message has been received, the "Sending..." label is removed.

To learn more about the useOptimistic Hook, see the reference documentation.

Other ways to control form resets

The examples above keep every submitted value by storing it before the reset. You can also choose which values survive, or when the reset runs:

  • Keep values only when validation fails. Return the same state shape from every submission. When validation fails, include the submitted FormData and read each field with state.submitted?.get('title') ?? ''. When validation succeeds, set that FormData to null so the reset clears those fields. useActionState shows this pattern.

  • Skip the reset with onSubmit. Handle the submission in onSubmit, call e.preventDefault(), and run the Action inside startTransition. Because the form's action does not run, React does not reset the form.

  • Reset at a specific moment. Call the form element's reset() method to immediately reset uncontrolled fields to their default values. To schedule a reset as part of an Action or Transition, call requestFormReset from react-dom instead.

  • Reset the form and the component state together. Change the key of the component that renders the form. React recreates the component and its DOM, which resets the fields and any local state.

Troubleshooting

My form fields are cleared after submission

When a function passed to action or formAction succeeds, React resets the form's uncontrolled fields to their default values. Text fields without a defaultValue become empty. Returning a validation error instead of throwing also triggers this reset.

To keep a submitted value, store it in state and pass it to the field's defaultValue. See Preserving form values after an Action for examples, or preserving values when validation fails.
